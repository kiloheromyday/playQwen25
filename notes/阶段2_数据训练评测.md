# 阶段 2：从 toy batch 到真实文本训练管线

这一阶段解决的问题是：模型虽然已经能在固定 batch 上过拟合，但还没有一个像预训练一样的“数据进入系统、训练、验证、保存”的闭环。

## 1. 为什么要按文档切分 train/valid

假设一篇文章被切成很多 token。若先把所有文章拼成一个长 token 流，再随机切 train/valid，同一篇文章的相邻片段可能落到两个集合里。模型在验证集上看到的内容其实已经在训练集附近出现过，这会让 validation loss 看起来虚低。

本阶段的顺序是：

```text
文件 -> 清洗 -> 去重 -> 文档级 train/valid 切分
     -> 只用 train 文档建立 tokenizer
     -> 分别 tokenize -> 追加 EOS -> pack 成固定长度序列
     -> DataLoader
```

`EOS` 是一篇文档结束的标记。它告诉模型：“这一篇内容到这里结束，下一段不一定属于同一个上下文。”

## 2. 清洗和去重做了什么

当前教学管线只做保守处理：

- 统一 Windows 和 Unix 换行；
- 删除空字符；
- 删除行尾多余空格；
- 把连续三个以上空行压缩成两个；
- 对清洗后的文本计算 SHA-256，完全重复的文档只保留第一次。

这不是生产级网页清洗器。真正的大模型数据还要处理 HTML、广告、乱码、个人信息、版权、语言比例、质量评分和近似重复。

## 3. Tokenize 和 pack 的关系

Tokenizer 把文字变成整数 id。例如：

```text
“模型” -> [42, 17]
```

模型训练通常需要固定长度的 `[batch, sequence_length]` 张量。`pack` 把多个文档的 token 串接起来，再按固定长度切块。当前版本会丢弃最后不足一个完整序列的尾部 token，这是教学实现里最简单的选择。

注意：丢弃尾部 token 会损失少量数据；生产训练通常会统计损失比例，或设计更完整的 padding/packing 策略。

## 4. loss 和 PPL 是怎么得到的

输入长度为 `T` 的序列：

```text
x0, x1, x2, ..., x(T-1)
```

模型在位置 `0` 的输出预测 `x1`，位置 `1` 的输出预测 `x2`，所以真正参与 loss 的位置数是 `T-1`。每个位置都有一个词表大小的 logits 向量，交叉熵取出真实下一个 token 的概率并平均：

```text
average_loss = 所有有效目标 token 的交叉熵平均值
PPL = exp(average_loss)
```

PPL 不是准确率。它可以粗略理解为模型面对下一个 token 时的平均不确定程度，数值越低通常越好，但只能在相同 tokenizer、数据处理和评测集合下比较。

## 5. 训练入口如何验证

运行：

```powershell
python main_data_pipeline.py
python main_train_pipeline.py --steps 30 --device cuda
```

入口会打印文档数、train/valid 文档数、pack 后的序列数、词表大小、train loss、valid loss、valid PPL、当前学习率和 tokens/s，并保存 checkpoint 与 tokenizer。

本阶段的“小验收”不是要求 PPL 达到某个官方数值，而是检查：

1. train 和 valid 文档没有重叠；
2. 每个 batch 形状正确；
3. loss 是有限值；
4. 训练后能够保存 checkpoint；
5. 用 `--resume` 能继续训练，scheduler 和随机状态也被恢复。

## 6. warmup 和 cosine 学习率

训练刚开始时，模型参数还没有形成稳定的更新方向。warmup 让学习率从较小值逐渐升高，减少初始阶段的剧烈更新。后面的 cosine decay 让学习率平滑降低：

```text
学习率：小 -> 逐渐升高 -> 逐渐降低
```

这只是一个常见基线，不等于 Qwen2.5 官方完整的学习率配置。复现时必须把学习率、warmup token 数、总训练 token 数和 batch size 一起记录。

## 7. 向师兄汇报的说法

我把前一阶段的固定 toy batch 扩展成了文档级预训练管线：先清洗和去重，再按文档切分 train/valid，只用训练文档建立教学 tokenizer，之后分别 tokenize、追加 EOS、pack 和 DataLoader。训练入口现在能输出 train/valid loss、PPL、tokens/s，支持梯度累积、BF16、warmup/cosine 和恢复训练。当前数据仍是本地小语料，下一步需要接入官方 tokenizer、规模更大的许可数据，并在多卡服务器上验证分布式吞吐和扩展效率。
