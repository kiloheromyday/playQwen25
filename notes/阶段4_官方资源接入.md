# 阶段 4：官方 tokenizer 和 config 的接入边界

## 1. 为什么不能把字符级 tokenizer 当成 Qwen tokenizer

当前项目的 `SimpleCharTokenizer` 是教学工具：中文通常按单字切分，英文和代码也按字符切分。真正的 Qwen tokenizer 是子词 tokenizer，词表更大，常见片段会被合并成更少的 token。

这会影响很多东西：

- `vocab_size` 不同，LM head 的输出维度不同；
- 同一句话的 token 数不同，训练吞吐和上下文长度不同；
- loss 和 PPL 不可直接横向比较；
- 训练数据 packing 后的边界不同。

所以切换 tokenizer 时必须同时切换 config 中的 `vocab_size`，并把 tokenizer 文件和实验 checkpoint 一起记录。

## 2. 当前代码支持什么

`QwenConfig.from_hf_json` 会从本地 Hugging Face `config.json` 读取本项目使用的字段，忽略官方配置中本项目还没有实现的额外字段。它不声称已经实现了所有 Hugging Face 配置行为。

`QwenTokenizerAdapter` 通过 `transformers.AutoTokenizer` 接入本地 tokenizer 文件。入口使用 `local_files_only=True`，因此不会因为一个 smoke test 意外联网下载资源。

运行：

```powershell
python main_official_adapter.py --model-path C:\path\to\local\Qwen-model
```

需要该目录至少包含 `config.json` 和 tokenizer 相关文件；当前环境没有官方模型文件时，这个入口不能凭空生成它们。

## 3. 为什么接入后还不能说“完成官方复现”

即使结构、config 和 tokenizer 都对齐，完整复现仍需要：

- 与官方相同或可比的数据；
- 清洗、去重、混合比例和采样权重；
- 训练 token 数、global batch size、学习率和 warmup；
- 精确的并行策略、通信实现和 checkpoint 规则；
- 官方评测任务和推理设置。

这些因素都会改变最终能力。当前项目的准确表述仍然是：Qwen2.5-style 教学实现，正在逐步对齐公开结构和训练系统。

## 4. 向师兄汇报的说法

我已经把官方资源接入做成了本地适配边界：可以从 Hugging Face `config.json` 读取模型形状，也可以在不联网的情况下加载本地 Qwen tokenizer。当前代码不会把字符级 tokenizer 的实验结果冒充官方 tokenizer 结果；拿到服务器上的模型文件后，可以先用 `main_official_adapter.py` 验证 config、词表和 encode/decode，再替换训练管线。
